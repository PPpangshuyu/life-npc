# 单场景快速制作

适用于固定人物、一个场景、约 5–8 秒且动作库已有相符动作的短片。目标是人物已确认、输入完整后约 300 秒交付；这是预算，尚非端到端时限保证。首次角色确认、新道具/新视角/新复杂动作需要额外准备。记录总经过时间、用户等待时间及实际制作时间，不把超时隐藏在“初始化”中。

## 先决定能复用什么

查看 `DATA_ROOT/motions/catalog.json`（若存在），只读相符条目，不扫描历史全部运行。`approved_visual_sha256` 对应当前已确认的 人物资料中 `approved_visual` 指向的当前批准图，不要拿真人原照的哈希比较。匹配服装、画风、朝向、视角、道具及动作；检查条目中的质量限制与是否获得用户认可。`usable_for_animation:false` 的条目不可作为动画缓存。文件变化、角色更换或道具遮挡关系变化时，不能继承旧检查结果。只有动作本身通过检查的素材才可用作动画；角色绘画参考不能替代连续动作。

复用时把所需素材复制到本次 `DATA_ROOT/runs/.../assets/`，保留来源记录。人物、透明轮廓、配准基准与道具一起复用；只改背景、全局位置、尺度、动作时序及必要的独立阴影。新背景先按角色视角和光向生成，为人物留出合理的地面与前后遮挡。源锚点不随透明边界改变而移动。

## 时间预算与执行

| 阶段 | 目标预算 | 操作 |
| --- | --- | --- |
| 输入与匹配 | 20 秒 | 复用已确认人物，匹配动作素材，确定机位与路径 |
| 新图像 | 180 秒 | 命中动作库时通常只生成一张环境；没有命中则说明还需准备动作，不承诺五分钟 |
| 配置与合成 | 40 秒 | 使用现有 JSON 驱动脚本，导出完整视频 |
| 实际视频检查 | 40 秒 | 解码每个显示姿态及首尾，集中看头发、手、道具、鞋底、遮挡 |
| 整理交付 | 20 秒 | 按照片分别交付完整 MP4，形象与关键帧留存工作目录，保存实际耗时 |

生成服务可能排队或单次超出预算；不应把预算写成测得的运行时间。超过预算时给出当前原因并继续完成已授权工作。只在有具体缺陷时重新生成，修复相关素材；若修复仍必要，明确超时而非带缺陷强行交付。无需每次重复创建诊断工具、读取全部历史、输出多套相同检查图或安排多轮相同复核。

本地编码速度与图像生成耗时分别记录；素材已备齐的几秒合成不能作为首次完整流程的速度证明。

## 现成合成入口

分层人物调用：

```bash
python3 "$SKILL_ROOT/scripts/render_layered_poses.py" --help
python3 "$SKILL_ROOT/scripts/render_layered_poses.py" "$RUN_DIR/composition.json"
```

路径相对于 JSON 所在目录；各姿态的 `anchor` 是源 PNG 坐标，`path` 中的 x/y 是该锚点在输出中的位置。`scale` 为输出像素/源像素。每一时刻只显示一个人物，不混合两个姿态。具体配置与计时字段以脚本帮助和实际结果为准。使用现有脚本不等于动作质量通过；仍需查看实际解码画面。素材本身滑步或姿态不合理时，不能靠交叉淡化掩盖。

需要连续走路且已有独立肢体素材时，使用 `scripts/render_skeletal_walk.py`；素材与配置要求见 [production.md](production.md)。未准备好躯干、完整腿部和关节坐标时，先完成素材准备，不能将四张静态图循环当作连续步态。

多个场景可复用同一动作素材，但环境生成、构图和检查按场景增加；每张照片分别导出一个完整视频，只有用户要求时才额外拼接合辑。没有实测前不把单场景五分钟推广为任意多场景五分钟。输出保留默认 30 fps；减少输出帧率通常不能减少图像生成轮数，也不会修复源姿态缺陷。

## 网页和外部服务

图片序列合成网页只替代编码/剪辑，不会理解并补全用户描述的行为。优先本地脚本，省去上传、网页操作与下载；如用户要求网页，可用其现有账号和可访问工具操作，不擅自开通付费服务。

需要由一两张图直接生成复杂运动时，图生视频服务可以作为另一种方案，但需独立检查身份、手脚、道具和轮廓，不能保证无变形或固定时限。批量自动化优先使用有正式 API 的服务，而不是维护脆弱的网页点击流程；接入前确认实际账号、费用和可调用能力。当前本地快速模式不依赖外部视频生成账号。

所有身份图和动作缓存均为私人本地资源。公开版本只提供代码、说明及可公开的示例素材，不把当前人物缓存当作公共默认人物。
