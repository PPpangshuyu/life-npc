# 动作制作与画面检查

按当前方法读取相关部分。目标是可辨认、动作清楚、没有明显破损的个人生活短片，而非每次重复某个试片的参数。

## 场景生成与连续性

给图像工具提供固定人物图、场景参考及角色在该场景的明确动作。首张场景关键帧应同时确定相机、人物比例、物件位置、衣服和完整发型。后续帧以这张场景帧为编辑底图，逐次只改动作需要变化的部位。

人物轮廓应留有余量：头顶、后侧头发、发梢、手肘、鞋底不贴裁切框。坐姿可以自然遮住下肢，但必须区分真实桌面遮挡和透明蒙版漏裁。主角动作涉及手机、鼠标、杯子等物件时，先明确哪只手做什么、每个物件的可见面和握持位置。正面未镜像视角下人物左手通常位于画面右侧、右手通常位于画面左侧；侧面或交叉双臂时沿各自肩、肘、腕检查连接，不凭左右屏幕坐标判断。不要翻转整图来补救错误。

当剧情需要观众看到打开应用、滑动内容或屏幕文字时，手机必须露出正面玻璃显示屏与合理的手指遮挡。后壳贴纸、相机模组或背面的图标不能代替屏幕；必要时改变手机角度或机位，同时保持人物解剖学左右手正确。这不要求所有手机场景都采用相同身体布局。

动作例：工位学习时，显示器为论文 PDF；人物左手点鼠标，右手持手机打开抖音、滑动观看，最后低头偷笑。要让论文版式、手机用途、两只手和表情变化都在镜头中可见。可从原照片的空座位视角改成三分之四正面视角，同时保留蓝色隔板、木桌、窗帘、显示器与常见桌面物品。

## 系列色调

默认色彩约定在 `SKILL_ROOT/assets/style/color-look.json`：低饱和暖灰与褐灰基底，天空与水面适度收敛蓝绿，肤色自然，高光温和，暗色材质保留层次。人物服装、发型和发色以当前用户批准图为准。可加入用户已认可的本地画面作为系列参考，公开包不要求任何私人参考图。不要用泛白雾、重噪点或模糊代替质感。

新场景生成时把这个色彩约定与人物、环境参考一同约束。对已有片段只做色调统一时，复用已确认人物与原动作，优先调整颜色；不为调色重新生成图像、改变人物轮廓或重复请求人物确认。后续交付的代表性关键帧也应来自同一调色版本。

每个场景根据自身光照确定一套固定参数，并保持到该场景结尾，避免逐帧自动曝光、白平衡或直方图匹配引起闪烁。先比较肤色、当前服装、发色与中性物件，再检查天空、植被与场景大色块；不要用整幅图的直方图强行匹配面积不同的天空、球场和办公室。

- 晴天保留更明亮的自然光与清楚阴影，适当压低过艳的蓝天、玻璃蓝和绿植，不把晴天压成阴天。
- 办公室保留中性灯光，白纸、论文屏幕与灰隔板可辨，避免整幅涂黄或压暗。
- 傍晚保留暖色晚霞、偏冷暗部和灯光，适当收敛紫红、蓝紫与高饱和亮部，不把晚霞改成灰色白天。

参数按实际素材判断，不能为统一数值牺牲上述光感。检查调色后的实际视频首、中、尾和场景切换：深色材质纹理没有糊成一块，皮肤无明显偏色，高光不过度溢出，道具仍可辨认，气泡与文字可读，颜色不随帧跳动。色调统一不等于改变各片原有几何风格或动作方法。

已有视频需要调色时，可用 `scripts/grade_video.py` 生成固定 33³ LUT 并调用 FFmpeg；执行 `--help` 查看参数。`assets/style/grading-starting-profiles.json` 提供 `daylight`、`office`、`dusk` 三种起点，适用于比目标更鲜艳的源片，不能反复套用到已经符合目标的画面。先以 `--config 配置文件 --profile 场景类型 --input 源视频 --output 预览.png --frame-time 秒数 --lut-output 工作目录/调色.cube` 检查同一帧；确认合适后省略 `--frame-time`，输出改为新 MP4，已有 LUT 需加 `--overwrite`。参数和视频均使用实际本地路径，保留原片，实际解码后再交付。

## 心情与内心想法

每张场景照片配“做什么＋心情如何／思考什么”。行为通过实际动作完成，心情通过表情、姿态与动作节奏表现；提供心情／想法时默认在人物上方添加同画风气泡。情绪优先采用易懂图标，具体思考可用简短中文小窗；用户要求无气泡、仅图标或指定文字时按其要求，未提供心情时不强制补充。例如“疲惫困倦，想上床睡觉”可用床、枕头与 Zzz 组成图标，如 `DATA_ROOT/mood-icons/` 中有已检查且画风相符的素材，可复用；否则生成新图标；“犹豫是否吃麦当劳”可用“吃不吃麦当劳呢”的小窗。这些例子不限定其他场景的图案或文案。

图标内容与气泡边框、厚度、光照和纹理都应延续当前画风：复古低多边形、偏灰低饱和、粗糙低分辨率贴图但边界清楚。不能只让床符合画风，却套用圆滑卡通气泡；不默认采用扁平 emoji 或现代光滑 UI。

图标采用独立素材与合成层，优先复用画风和语义相符的现成图标，否则生成清晰的新素材。根据角色的头部位置、整体缩放和道具轮廓设置跟随锚点，在角色上方或邻近上方留出间隔；撑伞时安排在伞侧上方等空处，不能压住头发、脸或伞面。逐输出帧更新位置，保持图标结构稳定，不将其烘进人物源帧或送入人物光流、蒙皮和姿态插值。空间不足时调整布局或比例，避免贴边、跳位或被裁切。

检查实际导出视频的开始、路径中段、结束和气泡出现／消失时刻：内容能看懂，气泡跟随稳定，轮廓与人物、道具留有间隔，出现时机与对应情绪／思考动作一致。具体想法只保留必要的短句，中文文字作为独立清晰图层合成，不自动增加底部字幕。

已有视频只需加心情时，优先用 `scripts/add_mood_overlay.py "$RUN_DIR/mood.json"` 独立叠加，不重新生成人物和动作。配置提供 `source_video/icon_png/output/display_width`；有骨骼逐帧状态时用 `tracking_states` 配合源图的 `source_anchor/source_track_point/source_top_bounds` 和 `clearance` 跟随，路径相对于配置文件。没有状态时可提供固定 `position:[x,y]`，但不能冒充随人物跟踪。使用 `--help` 查看契约，按实际构图设置间距；输出后仍检查 MP4 本身。

## 分层姿态动画

适用于动作幅度较大、肢体交叠明显，或局部插值不能保持结构的段落。

1. 先安排动作相位，例如迈步、承重、停稳、抬手，而不是先定一个通用帧数再填图。复杂相位需要更多中间姿态，停顿可以复用同一姿态。
2. 固定背景与摄影机。人物采用同尺度、同基准的透明图层；用脚底接地点、座椅接触点或躯干稳定点做配准，避免随素材边界变化而跳动。
3. 每一时刻只显示一个完整人物姿态。直接切换姿态，不在两个人物之间做透明交叉淡化；需要更柔和时先增加真实中间姿态。
4. 人物整体位置用刚性平移与必要的整体转向，不对未分离的人物整图随意拉扯。已有语义明确、补齐遮挡轮廓的独立肢体图层时，可用骨骼与连续蒙皮表达关节动作；头发、脸和道具保留稳定图层。鞋子承重时锁定接地点，避免身体移动但脚在地面滑动。
5. 若分段接到另一视频，使用相同的边界姿态或匹配静止关键帧，让姿态、机位、阴影与物件位置连续。

可用 HyperFrames 进行分层时间轴合成；使用时读取并遵循可用的 HyperFrames 与 CLI skills，执行所需检查后导出。简单局部合成也可用已安装的 FFmpeg，不必为使用本 skill 安装桌面视频软件。

固定背景与透明姿态的常规合成，优先运行 `scripts/render_layered_poses.py`，用 `--help` 查看 JSON 配置契约。配置和素材路径相对于本次配置文件解析；不要从旧运行复制机器绝对路径。复用素材及五分钟目标见 [fast-production.md](fast-production.md)。

自然步行需额外检查一个完整周期：左右腿交替、支撑脚着地停留、摆动脚前移和抬起、膝盖弯曲方向、髋部承重起伏。若用二维骨骼，按脚接地点求解髋—膝—踝关系，双支撑时平滑交接身体高度；不能用固定过低的髋部高度造成蹲走，也不能为锁脚而把腿拉长。宽裤腿和关节遮挡适合单一连续蒙皮；多个旋转裁片重叠可能形成双裤脚和黑色尖楔，需从实际渲染确认。检测到循环姿态没有真正换腿、鞋底滑动或姿态跳位时，停用该步态缓存。

已有完整上身透明图层和补齐遮挡轮廓的中立单腿素材时，可调用 `scripts/render_skeletal_walk.py "$RUN_DIR/walk.json"`；先用 `--dry-run` 输出一周期预览。它逐帧计算两腿 IK、支撑脚锁定和连续纹理蒙皮，不生成三维网格，也不理解未分离的完整人像。JSON 中 `upper_body` 提供 `image` 和源坐标 `pelvis`；`legs` 恰好两项，每项提供 `image`、源坐标 `hip/knee/ankle/toe/sole`、`texture_scale`、`pelvis_offset`、相差 0.5 的 `phase` 及近远层级 `depth`；`path` 各项为 `time/x/y/scale`，x/y 为地面基准。另设 `background/output/width/height/fps/duration`。路径相对于配置文件。

二维屏幕腿长与大幅纵深位移可能冲突，表现为额外屈膝或上坡感。没有真实三维投影时，优先选择与场景相符的横向或缓纵深路线，再检查完整步态。足底横向偏置应表达站距，不能大到抵消半步前进距离、让同一只脚一直领先。解析脚锁和骨长可达只是技术检查，仍需查看实际鞋底、裤腿边界及身体运动是否自然。

## 局部运动补偿

适用于相邻源图构图稳定、变化较小、遮挡关系变化很少的动作。它根据像素推算中间状态，不能理解哪一块一定是头发、手指或手机。

- 先比较源关键帧：脸部比例、发型、衣服纹理、手指数、道具尺寸和静止区域均应一致。源帧已改变身份或结构时，先修源图。
- 运动区域应包含全部运动轮廓和合理余量。摇头时包括头顶、刘海、后发与活动发梢；挥手时包括整个手、手指、必要前臂和位移路径。
- 从全程同一个固定基底中替换这一区域，只对区域内帧序列做运动补偿；保持其他区域稳定。边缘过渡放在变化少的位置，柔边不能掩盖漏发梢。
- 不让 PDF 正文、手机文字或 UI 图标参与不必要的插值。需要可读内容时可作为独立平面覆盖；屏幕或握持姿态变化时同步配准，不能悬浮或穿过手指。
- 先导出一个完整动作周期，逐帧看中间时刻。出现双轮廓、拉长的手指、脸部融化、边缘条带或背景被拖动时，减小动作差异、补充源姿态、缩小处理范围或换分层方法。
- 快速闭眼、视线跳转等幅度虽小，仍可能补出双重眼睛轮廓。源姿态正确但插值失败时，可在这个短区间改用明确姿态直接切换，必要时加入一两个中间姿态；其他平稳的点头或微笑仍可使用局部补帧。这是按实际缺陷选择的局部处理，不要求所有眼部动作都切换姿态。
- 用当前可用 Python 3 执行 `python3 "$SKILL_ROOT/scripts/render_local_motion.py" --help` 查看本地 ROI 合成契约；其中 `SKILL_ROOT` 是本 skill 的真实根目录。配置文件中的素材与输出路径相对于配置 JSON 所在目录。正式渲染前可用 `python3 "$SKILL_ROOT/scripts/render_local_motion.py" "$RUN_DIR/motion.json" --dry-run` 验证计划，其中 `RUN_DIR` 为本次制作目录的绝对路径。不要猜测参数或把脚本运行成功等同于视觉检查通过。

配置中每个帧条目的可选 `transition` 指定**到达该帧**的方式：默认 `"mci"` 对上一帧到这一帧做运动补偿；`"cut"` 将上一源姿态保持到当前帧的 `time`，再直接换到当前源姿态，不做淡化。以下仅是 `frames` 数组示例，需放进完整配置，并使用实际图像与时间：

```json
[
  {"image": "look-up.png", "time": 0},
  {"image": "look-down.png", "time": 0.133333333, "transition": "cut"},
  {"image": "smile.png", "time": 1, "transition": "mci"}
]
```

## 人物透明轮廓

优先让图像工具直接提供透明素材。若已有完整场景素材且必须抠图，保留原始 RGB，技术修补只改变 alpha；创意重绘使用图像编辑工具。

黑发与暗窗、海报、阴影颜色相似时，结合原图的发束走向、光照、与脸和肩部的连续关系、前后遮挡判断。不得把“很黑”当成背景，也不得把背景黑块全部补成头发。旧蒙版只作为待检查结果，不是人物真实边界的依据。

逐张把原图与抠图并排，在中性纯色和明亮棋盘背景上查看。以 100% 至 300% 的头部与手脚裁切图检查：

- 头顶轮廓、刘海、后脑勺、肩后长发、分叉发梢和孤立细发束；裁切范围要覆盖最长发丝。
- 袖口、手指、手机握持关系、裤腿、鞋尖、后跟和鞋底。
- 人物应保留的部位是否透出了背景，以及人物外部是否黏着原场景碎片。

对易混区域记录原图中明确属于头发的点及邻近明确背景点，检查前者 alpha 保留、后者透明。仅统计蒙版内部没有透明洞，不能证明轮廓外没有漏掉头发。源图本身缺失的肢体需重新生成或编辑，不能靠填满 alpha 恢复。

## 导出后检查

`python3 "$SKILL_ROOT/scripts/inspect_video.py" --help` 显示元数据与实际视频帧提取选项。例如 `python3 "$SKILL_ROOT/scripts/inspect_video.py" "$RUN_DIR/deliverables/video.mp4" --output-dir "$RUN_DIR/review" --times 0,0.5,1,2.9 --config "$RUN_DIR/motion.json"`，将时间点和路径替换为实际内容；仅在使用局部运动配置时加 `--config`。检查导出 MP4 本身，不能只检查预览页或中间 PNG。

- 核对帧率、尺寸、总时长与实际帧数。关键帧密度和输出帧率分别记录。
- 分层动作至少检查每个实际显示的姿态、人物开始和结束位置；放大有头发与手脚的区域。
- 局部插值检查两个源姿态之间的中间帧，尤其是最大运动与遮挡变化附近。静止源帧正确并不能证明中间帧正确。
- 检查每个场景开始、结束及切换前后。多人影、缺块、变形、跳位、屏幕闪烁和物件穿透应修复后重新导出。
- 每张照片分别导出并检查完整视频，按输入顺序交付；人物图和代表性关键帧默认保留工作目录。用户另要合辑时，可用直接切镜或指定转场额外拼接，仍保留独立视频。默认不对不同场景或不同人物姿态做全画面光流混合。
- 预览更新应使用新版本文件名或资源 URL，防止缓存显示旧蒙版；最终交付链接必须指向实际检查的文件。

保存一份简短运行记录，关联输入、人物确认状态、提示词、代表帧、导出文件和实际检查证据。使用“已查看哪些帧与区域”的具体描述，避免凭技术校验给出无缺陷保证。
